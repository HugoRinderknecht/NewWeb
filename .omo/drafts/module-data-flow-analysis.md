# 项目模块间数据交互与联动更新分析报告

## 一、项目概述

**项目名称**: Art Design Pro (dreamcraft-astra)  
**技术栈**: Vue 3 + TypeScript + Pinia + Vue Router + Element Plus + Axios  
**业务定位**: 短剧/视频创意生产管理平台

## 三、模块间数据交互分析

### 3.1 核心数据流：项目→剧本→分镜→视频 生产管线

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   项目管理   │───▶│   剧本管理   │───▶│   分镜管理   │───▶│  视频生成    │
│  (Project)   │    │  (Script)    │    │ (Storyboard) │    │(Video Gen)  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       │                  │                  │                  │
       ▼                  ▼                  ▼                  ▼
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   角色管理   │    │  人物小传    │    │   资产关联   │    │  积分扣减    │
│ (Characters) │    │ (Profiles)  │    │  (Assets)    │    │ (Points)    │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

**数据依赖关系**:
- 剧本依赖项目ID (`projectId`)
- 分镜依赖剧本ID (`scriptId`) 和分集ID (`episodeId`)
- 视频生成依赖分镜ID (`storyboardId`)
- 资产通过关联绑定到分镜

### 3.2 Store层数据交互矩阵

| 源Store | 目标Store | 交互数据 | 交互方式 | 触发条件 |
|---------|-----------|----------|----------|----------|
| `user` | `menu` | 登录状态、用户信息 | 直接调用 | 登录/登出 |
| `user` | `worktab` | 用户ID | 直接调用 | 登出时清理标签 |
| `user` | `setting` | 主题设置引用 | computed | 设置读取 |
| `menu` | `worktab` | 首页路径 | 间接依赖 | 路由跳转 |
| `project-data` | `script-project` | 项目列表 | storeToRefs | 项目切换 |
| `script-project` | `project-data` | 剧集数量更新 | 直接调用 | 剧本增删 |
| `setting` | 全局 | 主题、布局配置 | 响应式 | 设置变更 |

### 3.3 关键联动更新机制

#### 3.3.1 用户登出联动链

**触发源**: `userStore.logOut()`

**联动更新序列**:
1. 清空用户信息 (`info = {}`)
2. 重置登录状态 (`isLogin = false`)
3. 清空令牌 (`accessToken = ''`, `refreshToken = ''`)
4. 清空锁屏状态
5. 调用 `menuStore.setHomePath('')` - 重置首页路径
6. 调用 `resetRouterState(500)` - 清除动态路由
7. 跳转登录页

**潜在问题**:
- ⚠️ 未清理 `worktabStore` 标签页（设计如此，支持同用户重登录保留）
- ⚠️ 未清理 `settingStore` 设置（持久化到localStorage，符合预期）
- ⚠️ 未清理 `project-data` 数据（可能导致数据残留）

#### 3.3.2 项目切换联动链

**触发源**: `scriptProjectStore.setCurrentProject(projectId)`

**联动更新**:
1. 更新 `scriptProjectStore.currentProjectId`
2. 页面重新加载剧集列表 (`fetchGetProjectEpisodes`)
3. 重新加载资产数据 (`fetchGetProjectAssets`)
4. 重新加载角色数据 (`fetchGetCharacterList`)

**潜在问题**:
- ⚠️ `project-data` Store 的 `currentProjectId` 未同步更新
- ⚠️ 两个Store各自维护独立的 `currentProjectId`，可能不一致

#### 3.3.3 剧本保存联动链

**触发源**: 脚本编辑器保存操作

**联动更新**:
1. 调用 `fetchUpdateScript` API 更新剧本
2. 更新本地 `episodeList` 中对应项
3. 调用 `projectStore.updateEpisodeCount` 更新剧集计数
4. 更新编辑器状态 (`saveStatus = 'saved'`)

**潜在问题**:
- ⚠️ API调用成功后才更新本地状态，失败时状态不一致
- ⚠️ 多标签页场景下无跨标签同步机制

#### 3.3.4 审核流程联动链

**触发源**: 审核决策操作

**数据流**:
```
提交审核 → 创建审核任务 → 审核人认领 → 做出决策 → 更新状态
    │                                              │
    ▼                                              ▼
剧本/分镜状态更新                              通知发送
```

**涉及模块**:
- `review.ts` API - 审核任务管理
- `script.ts` API - 剧本审核状态
- `storyboard.ts` API - 分镜审核状态
- `notification.ts` API - 审核通知

### 3.4 API层数据流模式

#### 3.4.1 认证令牌注入

```typescript
// utils/http/index.ts
axiosInstance.interceptors.request.use((request) => {
  const { accessToken } = useUserStore()
  if (accessToken) request.headers.set('Authorization', accessToken)
  return request
})
```

**数据流**: `userStore.accessToken` → HTTP请求头 → 后端认证

#### 3.4.2 401错误处理链

```typescript
// 触发条件: API返回401
handleUnauthorizedError() → userStore.logOut() → 清理所有状态 → 跳转登录页
```

**防抖机制**: 3秒内只触发一次，避免重复登出

#### 3.4.3 工作流SSE流式数据

```typescript
// api/workflow.ts
fetchExecuteWorkflowStream(workflowCode, params) {
  return fetch(`${baseURL}/api/dify-workflows/${workflowCode}/execute-stream`, {
    headers: { Authorization: getAuthToken() }
  })
}
```

**数据流**: 前端发起SSE连接 → 后端流式推送 → 前端实时处理

## 四、数据同步问题与潜在冲突点

### 4.1 🔴 高风险问题

#### 4.1.1 双Store项目ID不同步

**问题描述**:
- `project-data` Store 维护 `currentProjectId`
- `script-project` Store 也维护独立的 `currentProjectId`
- 两者无自动同步机制

**影响场景**:
- 在剧本页面切换项目后，返回项目列表页可能显示旧项目
- 分镜页面可能引用错误的项目上下文

**代码证据**:
```typescript
// store/modules/project-data.ts
const currentProjectId = ref<number>(1)  // 独立维护

// store/modules/script-project.ts
state: () => ({
  currentProjectId: 1  // 独立维护，无同步
})
```

#### 4.1.2 本地状态与API状态不一致

**问题描述**:
- 剧本保存时先更新本地状态，再调用API
- API失败时本地已更新，导致不一致

**影响场景**:
- 用户看到"保存成功"但实际未持久化
- 刷新页面后数据丢失

#### 4.1.3 登出后数据残留

**问题描述**:
- `project-data` Store 数据未在登出时清理
- 该Store未启用持久化，但内存中仍有残留

**影响场景**:
- 不同用户登录后可能看到前一用户的项目数据（内存中）

### 4.2 🟡 中风险问题

#### 4.2.1 多标签页数据不同步

**问题描述**:
- 浏览器多标签页间无数据同步机制
- 一个标签页的操作不会实时反映到其他标签页

**影响场景**:
- 标签页A删除剧本，标签页B仍显示该剧本
- 标签页A切换项目，标签页B仍显示旧项目

#### 4.2.2 并发操作冲突

**问题描述**:
- 快速连续导航时 `routeInitInProgress` 标记可能失效
- 多个API请求并发时无锁机制

**影响场景**:
- 快速切换页面可能导致路由初始化重复执行
- 并发保存可能导致数据覆盖

#### 4.2.3 缓存一致性问题

**问题描述**:
- `worktab` Store 使用 KeepAlive 缓存页面组件
- 关闭标签页时添加到 `keepAliveExclude`，但组件可能未销毁

**影响场景**:
- 重新打开已关闭的页面可能显示旧数据

### 4.3 🟢 低风险问题

#### 4.3.1 持久化数据版本兼容

**问题描述**:
- 使用 `StorageKeyManager` 管理版本化存储键
- 跨版本升级时需数据迁移

**缓解措施**:
- 已实现版本化键名 (`sys-v{version}-{storeId}`)
- 有数据迁移机制

#### 4.3.2 主题设置响应延迟

**问题描述**:
- `settingStore` 设置变更后需手动调用 `setElementThemeColor`
- 部分设置通过CSS变量生效，可能有渲染延迟

## 五、联动更新完整性评估

### 5.1 ✅ 实现良好的联动

| 联动场景 | 实现质量 | 说明 |
|----------|----------|------|
| 登出清理链 | ⭐⭐⭐⭐ | 完整清理用户相关状态，保留跨用户标签页 |
| 动态路由注册 | ⭐⭐⭐⭐⭐ | 完整的守卫链、权限验证、错误处理 |
| 401自动登出 | ⭐⭐⭐⭐ | 带防抖机制，避免重复触发 |
| 工作标签页管理 | ⭐⭐⭐⭐ | 支持固定、批量操作、缓存排除 |
| 主题切换 | ⭐⭐⭐⭐ | 暗色模式、菜单主题、Element Plus主题色 |

### 5.2 ⚠️ 需要改进的联动

| 联动场景 | 当前问题 | 建议改进 |
|----------|----------|----------|
| 项目切换同步 | 双Store不同步 | 统一为单一Store或添加同步机制 |
| 保存失败回滚 | 本地已更新 | 添加乐观更新回滚机制 |
| 跨标签同步 | 无同步机制 | 添加 BroadcastChannel 或 storage 事件监听 |
| 审核状态联动 | 依赖手动刷新 | 添加 WebSocket 实时推送 |
| 资产关联更新 | 需手动刷新 | 添加关联变更事件通知 |

### 5.3 ❌ 缺失的联动

| 缺失场景 | 影响 | 建议实现 |
|----------|------|----------|
| 实时协作通知 | 多用户协作无感知 | WebSocket 实时状态同步 |
| 级联删除更新 | 删除项目后子数据残留 | 添加级联清理逻辑 |
| 版本冲突检测 | 并发编辑无警告 | 添加乐观锁或版本号检测 |
| 离线操作队列 | 网络断开操作丢失 | 添加离线操作缓存和重放 |

## 七、改进建议

### 7.1 短期改进（1-2周）

1. **统一项目上下文Store**
   - 合并 `project-data` 和 `script-project` 的项目管理逻辑
   - 确保全应用使用统一的 `currentProjectId`

2. **添加保存失败回滚机制**
   - 实现乐观更新模式
   - API失败时回滚本地状态

3. **完善登出清理链**
   - 在 `logOut()` 中添加 `project-data` Store 清理

### 7.2 中期改进（2-4周）

1. **实现跨标签页同步**
   - 使用 `BroadcastChannel` API
   - 监听 `storage` 事件

2. **添加WebSocket实时推送**
