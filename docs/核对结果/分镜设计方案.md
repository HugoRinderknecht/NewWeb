# 分镜设计页面重构方案

## 一、现状分析

### 1.1 当前页面功能
- 简单的表格列表展示分镜
- 基本的CRUD操作（新建、编辑、删除）
- 搜索和状态筛选
- 统计概览卡片

### 1.2 存在的问题
1. **缺乏可视化分镜板**：只有表格视图，无法直观展示分镜序列
2. **未利用审核流程**：API支持完整的审核流程，但页面未实现
3. **缺少版本管理**：API支持版本历史和回滚，但页面未实现
4. **缺少配图管理**：API支持配图的增删查，但页面未实现
5. **缺少资产关联**：API支持资产关联，但页面未实现
6. **缺少AI功能**：API支持AI分镜拆解和重建，但页面未实现
7. **缺少镜头语言标注**：景别、运镜、镜头类型等信息未展示
8. **缺少批量操作**：API支持批量提交审核和删除，但页面未实现

```

                ↑
            撤回(草稿)

操作按钮：
- 草稿状态：[提交审核] [编辑] [删除]
- 待审核状态：[撤回审核] [查看详情]
- 已通过状态：[查看详情] [重新编辑]

```

- 加载状态的骨架屏

## 六、数据流设计

### 6.1 数据获取流程

```
页面加载
    ↓
获取 projectId（从路由或 store）
    ↓
调用 GET /api/projects/{projectId}/storyboards
    ↓
渲染分镜列表
    ↓
用户点击分镜卡片
    ↓
调用 GET /api/storyboards/{storyboardId}
    ↓
渲染详情面板
```

### 6.2 AI拆解流程

```
用户点击 [AI拆解]
    ↓
选择剧本和分集
    ↓
确认消耗积分
    ↓
调用 POST /api/projects/{projectId}/scripts/{scriptId}/episodes/{episodeId}/storyboard/decompose
    ↓
显示进度条
    ↓
轮询查询进度
    ↓
拆解完成，刷新列表
```
