本报告聚焦以下内容：

# 3. 数据处理流程分析

## 3.1 数据获取机制分析

项目中的数据来源主要包括以下三大类：

### 3.1.1 API 接口调用

API 接口调用是项目最核心的数据获取方式，覆盖绝大多数业务数据，如：

- 用户信息
- 项目列表/详情
- 团队信息
- 积分统计
- 分镜与脚本数据
- 系统管理数据
- 统计报表与趋势图数据

### 调用链路

```text
页面组件
  → Query Hooks
    → API 方法
      → API Adapter
        → Axios 封装
          → 后端 REST API
```

### 典型路径示例

以项目列表为例：

- 页面：`src/views/project/list/index.vue`
- Query Hook：`src/api/queries/project.ts`
- API 方法：`src/api/project.ts`
- 适配器：`src/api/adapter/http-adapter.ts`
- HTTP 实现：`src/utils/http/index.ts`

### 数据获取方式特征

1. **按业务域拆分接口**
   - `auth.ts`
   - `project.ts`
   - `team.ts`
   - `statistics.ts`
   - `script.ts`
   - `storyboard.ts`
   - `asset.ts`
   - `video.ts`
   - `workflow.ts`
   - 等
2. **查询与变更分离**
   - 查询：`useQuery`
   - 写操作：`useMutation`
3. **分页、条件查询、动态参数支持完整**
   - 支持 `computed` 参数驱动查询
   - 支持响应式 teamId / projectId / route 参数
4. **服务端状态缓存化**
   - 统一交给 Vue Query 管理缓存与失效

### 3.1.2 本地存储读取

#### 1）`localStorage`

#### 2）`sessionStorage`

### 典型存储内容

| ----------- | -------------- |

### 3.2.3 安全措施分析

#### 1）Token 认证机制

Axios 请求拦截器会自动从用户 store 中读取 token，并在请求头附加：

- `Authorization: Bearer xxx`

#### 2）401 自动刷新机制

HTTP 层实现了较完整的 token 刷新策略：

- 并发刷新合并
- 待重试请求排队
- 刷新成功后重发请求
- 刷新失败则强制登出

#### 3）请求超时与失败重试

- 超时时间：15 秒
- 最大重试次数：1 次

#### 4）请求去重

对于重复请求，使用唯一 key 管理 pending request，降低重复发送概率。

#### 5）响应缓存

内置 LRU 响应缓存，可缓存部分重复访问结果。

#### 6）表单前端校验

基于 `ElForm` + `rules` 执行：

- 必填校验
- 长度限制
- 输入 trim 处理

#### 7）锁屏密码散列存储

项目使用浏览器原生 `crypto.subtle.digest` 执行 SHA-256 哈希处理，避免锁屏密码明文存储。

#### 8）错误边界与异常页面

- 全局错误边界组件
- 403/404/500 错误页
- 全局错误处理注册

- 全局失败处理与局部失败提示配合存在
