# 修复计划

## 优先级 1：先修数据源和 ID 语义

1. 修复 `src/store/modules/project-data.ts` 与 `src/store/modules/script-project.ts`
   - 去掉默认 `'1'` 占位值。
   - 明确区分 `currentProjectId` 与 `currentScriptId`。
   - 增加项目/剧本加载与选中后的同步逻辑。
2. 修复剧本相关视图
   - 重点检查 `src/views/script/library/index.vue`、`src/views/script/write/index.vue`、`src/views/script/decompose/index.vue`、`src/views/script/profiles/index.vue`、`src/views/script/ai-review/index.vue`、`src/views/script/version/index.vue`。
   - 改成先获取正确的剧本标识，再调用需要 `scriptId` 的接口。
3. 修复资产与团队页面的 ID 取值
   - 统一使用 `route.params` / `route.query` 优先，其次 fallback 到 store。
   - 去掉对 `'1'` 的硬编码兜底。

## 优先级 2：修 API 签名与类型

1. 修复 `src/api/statistics.ts`
   - 让 `fetchGetTrends` 强制接收 `eventType`。
   - 与 `src/types/api/api.d.ts` 中的 `TrendParams` 对齐。
2. 补齐缺失类型
   - `ScriptDetail`、`ScriptVersion`、`TrendParams` 等与页面实际使用保持一致。
3. 对照报告逐项核查缺失函数
   - 优先核对 `dify.ts`、`ai-video.ts`、`video.ts`、`storyboard.ts`、`asset.ts`、`editor.ts`。

## 优先级 3：统一接入 adapter

1. 将 `src/api/*.ts` 逐个从 `@/utils/http` 迁移到 `getApiAdapter()`。
2. 保证 `http / mock / hybrid` 三种模式行为一致。
3. 先改基础模块，再改业务聚合模块，避免一次性大范围回归。

## 优先级 4：补充验证

1. 为已确认问题补最小验证路径。
2. 逐个检查报告中的“缺失函数”是否已有其他模块承接。
3. 最后再回头核对统计数字，确认报告中的模块数、函数数和文件数是否需要修正。

## 建议执行顺序

1. 先修 store 与 ID 取值。
2. 再修趋势接口和类型。
3. 再统一 adapter。
4. 最后做缺失函数对账与统计校准。
