## 二、问题 1：分集详情接口 404

### 2.1 现象

```
GET /api/scripts/{scriptId}/episodes/{episodeId} → 404
```

分集列表接口 `GET /api/projects/{projectId}/scripts/{scriptId}/episodes` 能正常返回数据，但用返回的 `episodeId` 去查详情时返回 404。

### 2.2 前端调用链路

1. 页面调用 `fetchGetScriptEpisodes(projectId, scriptId)` → 列表成功，显示分集
2. 用户/默认选中某分集 → `useEpisodeDetail(scriptId, episodeId)` 触发详情查询
3. 详情接口 404 → 全局错误提示弹出

### 2.3 API 文档定义

文档路径：`docs/API/剧本-拆解/api.json`

- 列表接口：`GET /api/projects/{projectId}/scripts/{scriptId}/episodes` → `ResultListScriptEpisodeVO`
- 详情接口：`GET /api/scripts/{scriptId}/episodes/{episodeId}` → `ResultScriptEpisodeVO`

两个接口返回的 VO 类型相同（`ScriptEpisodeVO`），理论上同一条记录在两个接口中应该都能查到。

### 2.4 可能的根因

#### 情况 A：列表与详情的数据源不一致
列表接口能返回某条分集记录，但详情接口查询时使用了不同的表、不同的过滤条件或不同的关联逻辑，导致同一个 `episodeId` 无法被详情接口查到。

#### 情况 B：返回了已失效/已删除的 episodeId
列表接口带出了某条逻辑删除的、历史残留的 `episodeId`，详情接口严格按主键查询时返回 404。文档中 `deleteEpisode` 的描述为"逻辑删除指定分集"，如果列表接口未过滤逻辑删除的记录，就会出现此问题。

#### 情况 C：列表接口返回聚合结果，详情接口返回实体结果
列表层把数据拼出来了，但详情接口要求实体真实存在；如果实体被归档、软删除，列表仍可能显示，详情却失败。

#### 情况 D：查询上下文不一致
列表接口按 `projectId + scriptId` 查询，详情接口只按 `scriptId + episodeId` 查询。如果后端对详情接口额外做了项目归属校验、权限过滤、租户隔离等，可能导致 404。

### 2.5 后端排查建议

1. 用列表接口返回的每个 `episodeId`，逐个验证详情接口是否都能查到
2. 检查详情接口是否额外做了以下过滤：
   - 逻辑删除过滤（`is_deleted` / `deleted` 字段）
   - 状态过滤（如只返回特定状态的分集）
   - 项目归属过滤（验证 episode 是否属于该 scriptId）
   - 权限过滤
   - 租户隔离过滤
3. 核查列表查询与详情查询是否来自不同表或不同 VO 装配逻辑
4. 确认列表接口是否过滤了逻辑删除的记录

## 三、问题 2：AI 处理状态接口参数不匹配

### 3.1 现象

前端调用 AI 状态轮询接口时，传递的参数与后端文档定义不一致，导致后端返回 400/500 错误。

### 3.2 文档定义

文档路径：`docs/API/AI-处理记录/api.json`

```
GET /api/ai-process/status?type={workflow_code}&businessId={id}
```

| 参数 | 位置 | 必填 | 说明 |
|------|------|------|------|
| `type` | query | 是 | 业务类型(workflow code) |
| `businessId` | query | 是 | 业务ID |

### 3.3 前端实际发送

```
GET /api/ai-process/status?scriptId={scriptId}&processType=CHARACTER_PROFILE
```

| 参数 | 文档要求 | 实际传值 | 是否匹配 |
|------|----------|----------|----------|
| `type` | workflow code | 未传 | ❌ 缺失必填字段 |
| `businessId` | 业务 ID | 未传 | ❌ 缺失必填字段 |
| `scriptId` | 无 | 传了 | ❌ 后端不识别 |
| `processType` | 无 | 传了 | ❌ 后端不识别 |

### 3.4 正确的映射关系

根据文档语义推断：

| 前端意图 | 应传参数 | 值 |
|----------|----------|-----|
| 业务类型 | `type` | `CHARACTER_PROFILE`（或其他 workflow code） |
| 业务 ID | `businessId` | `scriptId` 的值 |

即正确调用应为：

```
GET /api/ai-process/status?type=CHARACTER_PROFILE&businessId={scriptId}
```

### 3.5 后端确认事项

1. 确认 `type` 参数的可选值列表（如 `CHARACTER_PROFILE`、`SCRIPT_DECOMPOSE` 等）
2. 确认 `businessId` 在人物小传场景下是否应传 `scriptId`
3. 确认当缺少必填参数时，后端返回的是 400 还是 500（前端观察到的是"服务器内部错误"，说明后端可能返回了 500 而非 400）
4. 确认当无匹配记录时，后端返回的是 404 还是空 data（影响前端轮询是否需要降级处理）

## 四、问题 3：项目分集列表接口异常

### 4.1 现象

人物小传页面会请求 `GET /api/projects/{projectId}/episodes`，此接口主要用于 AI 生成前展示"可选分集"。如果此接口异常，也会触发全局错误提示。

### 4.2 文档定义

文档路径：`docs/API/剧本-拆解/api.json`

```
GET /api/projects/{projectId}/episodes → ResultListScriptEpisodeVO
```

### 4.3 后端确认事项

1. 确认此接口在项目无分集时是否返回空数组 `[]`（而非 404 或 500）
2. 确认此接口对已归档/已删除项目的处理逻辑
3. 确认此接口是否需要权限校验（如果需要，未授权时返回什么状态码）

---

## 五、后端修复优先级

### 第一优先级：修复 AI 状态接口参数校验
- 缺少必填参数时应返回 400 而非 500
- 提供清晰的错误消息，指明缺少哪些参数

### 第二优先级：修复分集列表与详情数据一致性
- 确保列表接口返回的每条记录都能被详情接口查到
- 如果存在逻辑删除，列表接口应过滤掉已删除的记录
- 或在详情接口中对逻辑删除的记录返回特定业务码（而非 404）

### 第三优先级：统一空数据返回语义
- `GET /api/projects/{projectId}/episodes` 无数据时返回空数组
- `GET /api/ai-process/status` 无匹配记录时返回 404 + 明确消息，或返回空 data
- 各接口对异常条件的返回码应与文档定义一致

## 六、附录：前端已发现的相关问题

以下问题前端将自行修复，列在此处供后端参考：

1. **AI 状态查询参数错误**：前端 `ai-process.ts` 传 `scriptId/processType`，应改为 `type/businessId`
2. **状态枚举大小写不一致**：前端部分代码用小写 `completed/failed`，部分用大写 `COMPLETED/FAILED`，需统一
3. **全局错误提示过于激进**：HTTP 层默认对所有非 401 错误弹 `ElMessage.error`，需增加分层控制
4. **剧本拆解绕过统一数据层**：页面直接调用 `fetchGetScriptEpisodes` 而非 Query Hook，导致缓存不联动
